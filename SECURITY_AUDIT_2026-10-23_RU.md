## Проверено
- Repository GitHub API: visibility=private.
- Offline Demo CI (run 39948957524): Android APK компилируется, проверка разрешений и загрузка артефакта успешны. В демо нет android.permission.INTERNET и нет Telegram-авторизации.
- Offline unit tests: безопасность манифеста, криптографические блоки, ошибки пароля/подмены, восстановление и тестовый pipeline; повторено локально 3 раза.

- Доступные правила: https://core.telegram.org/api/terms ; https://core.telegram.org/api/obtaining_api_id ; https://core.telegram.org/api/takeout ; https://telegram.org/tos/content-licensing .

## Блокирующие вопросы
1. API Terms §1.3 требует работу базовых функций обычных Telegram-клиентов. Узкоспециализированный клиент ТОЛЬКО для экспорта может не удовлетворять этому требованию. Не считать соответствие подтверждённым.
2. Telegram автоматически наблюдает за аккаунтами, использующими неофициальные API-клиенты. Ноль риска блокировки гарантировать нельзя. Даже документированный Takeout API не даёт иммунитет.
3. Экспорт v0.9 использует TDLib getChatHistory/downloadFile, а НЕ официальный MTProto takeout-процесс. Выгрузка сложных переписок, split ranges, кастомных эмодзи, редких типов медиа и полнота не верифицированы.
4. TDLib может временно сохранять незашифрованные медиа в приватном каталоге приложения. Нужно протестировать уничтожение после crash/power-loss, backup и Android scoped-storage/SAF.
5. Нативный libtdjson.so ещё не собран/подключён/испытан для настоящего экспортёра. Нельзя делать вывод о защищённости реальной авторизации, 2FA, session token, logout или сетевого трафика.
6. API credentials в APK могут быть извлечены; держать секреты пользователя, пароли, код авторизации и сессии вне GitHub/логов; разработческие ключи и лимиты нужно защищать и мониторить.
7. Пользователь должен явно запускать подключение и экспорт. Не делать массового автоматического чтения чатов или обхода FLOOD_WAIT; сохранять доступные только владельцу данные с учётом ограничений на контент.

## Запрет на выпуск
До отдельного review соответствия API terms, review licence dependencies, воспроизводимой сборки TDLib, прогона тестов на собственном безопасном тестовом аккаунте, анализа Android-сетевого трафика и QA больших/прерванных выгрузок Production APK не распространять и в важный личный аккаунт не входить.

## Более безопасный путь
1. Офлайн APK (фиктивный чат, фальшивые медиа) -> тестировать UI/локальное шифрование.
2. Отдельная тестовая Android-сборка с Telegram Test DC (не production), если доступен легитимный тестовый аккаунт.
3. Провести review соответствия специализированного read-only экспортёра правилам API/Content Licensing, при необходимости запросить официальное разъяснение.
4. Только после пунктов 1-3 оценивать допустимость и оставшийся риск использования обычного Telegram-аккаунта.

Частный GitHub защищает от публичного просмотра, но не исключает доступ GitHub, установленных приложений и явно приглашённых участников. Проверять доступ периодически.
