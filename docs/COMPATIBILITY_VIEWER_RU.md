# Контракт совместимости Exporter ↔ Offline Viewer

Проверено по приватным репозиториям (23.10.2026):

- **Vault Exporter / Offline Demo** сохраняет файл `.tva`: TVA1 (PBKDF2-HMAC-SHA256 + AES-GCM blocks) с ZIP внутри; `manifest.json`, `messages/page-*.jsonl`, `media-index/page-*.jsonl`, `media/...`.
- **telegram-offline-viewer.**, класс `app/src/main/java/org/openarchive/telegram/TelegramImporter.java`, сейчас распознаёт **`messages.html`** из папки стандартного Telegram Desktop-экспорта. Он НЕ расшифровывает и НЕ импортирует `.tva`.
- Следовательно, **сквозная интеграция экспортёр → читалка ещё не реализована**. Успешные испытания ZIP/TVA не доказывают возможность открыть архив в текущей читалке.

## Требования к адаптеру TVA

1. Выбор файла `.tva` через Android Storage Access Framework и ручной ввод пароля, никакого Telegram-логина.
2. Потоковая проверка AEAD/ZIP/CRC и схемы `manifest.json`, контроль дублей сообщений, путей, медиа SHA-256 и связи с ID.
3. Не показывать пользователю архив «полностью импортирован», пока проверка **всего** архива и финального AEAD-тега не пройдена.
4. Стадировать БД и медиа во временном защищённом месте, атомарно публиковать только после успешной проверки; при ошибке сохранять старую БД.
5. Избегать хранения открытых пользовательских медиа на общедоступном накопителе; не передавать пароль/содержимое в логи, серверы, crash-report SDK.
6. Совместимые голосовые, фото, видео, кружочки, файлы, ответы, пересылки, авторы и временные метки.
7. Проверить файл после экспорта, затем после передачи между устройствами, включая повреждения и обрыв копирования.

## Текущее решение

Продолжать безопасное офлайн-тестирование генератора `.tva`, НЕ заявлять end-to-end совместимость с читалкой. Для следующего этапа нужен отдельный приватный импортёр, а не рискованная Telegram-сессия.
