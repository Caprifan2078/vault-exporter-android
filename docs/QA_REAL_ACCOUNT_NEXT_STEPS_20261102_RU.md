# Real Telegram QA: безопасный план до покупки тестового аккаунта (02.11.2026)

## Что добавлено в QA-ветке

- Отдельная устанавливаемая сборка `qaProduction` (package `org.vault.exporter.qa`), не затрагивающая обычный Telegram и прежнюю sandbox-базу.
- Сборка заблокирована без явных `telegramEnvironment=production` и `approveProductionBuild=true`.
- Сборка заблокирована без действительных **собственных реквизитов разработчика** Telegram API; фиктивные значения `1` и 32 нуля запрещены.
- В интерфейсе заметное предупреждение «ТЕСТОВАЯ СБОРКА», а до первого входа доступна кнопка «Сначала проверить TDLib без аккаунта». Она отправляет только локальный запрос getAuthorizationState, без установки параметров и подключения к Telegram.
- Подготовлен **ручной** приватный GitHub Actions workflow `disposable-real-account-qa.yml`: сборка pinned official TDLib из исходников, изолированная APK, проверки разрешений, краткоживущий артефакт. В workflow не передаются SMS-коды, чужие сессии или переписки.
- Никаких изменений в `main`.

## Что ещё НЕ доказано

- В контейнере без Android SDK / NDK сборка APK не проводилась. Локально прошли статические gates, CI-contract, JNI-host, lifecycle tests; это не заменяет Android runtime.
- Ручной workflow пока **не запускался**. GitHub Actions может требовать наличия файла workflow в default branch для запуска через `workflow_dispatch`; ничего не переносить в `main` без ревью.
- Нет независимого аудита production APK, сетевого трафика, поведения на физическом Android или подтверждённого входа через TDLib.
- Для сборки нужны собственные API ID/hash приложения разработчика; конечному пользователю вводить их не потребуется. Секреты допускаются только в GitHub Actions Secrets; **не отправлять** их, коды входа или дампы сессий в чат.
- Exporter сейчас создаёт **зашифрованный .tva**, а не гарантированно совместимый ZIP/HTML из Telegram Desktop. Совместимость с отдельной читалкой нужно проверять специально.

## Порядок теста без потери 100 ₽

1. Настроить реквизиты разработчика в закрытом CI без публикации в коде.
2. Провести независимую ревизию workflow и QA-ветки, проверить реальную сборку APK.
3. Установить `org.vault.exporter.qa` и выполнить **«Сначала проверить TDLib без аккаунта»**.
4. Проверить отсутствие стороннего трафика, корректную работу экранов логина и разрешений.
5. Только тогда рассматривать покупку **одного** явно законно переданного тестового аккаунта. Запросы кода через TDLib; 2FA и email могут потребоваться дополнительно.
6. Создать новые искусственные сообщения/медиа на подконтрольных участниках; выгрузить, сверить содержимое, повторить после рестарта. Не экспортировать старые чужие переписки.
7. Если что-то не проходит — не покупать второй аккаунт, остановить тест и сохранить только обезличенные ошибки.

**Текущий статус: PRODUCTION APK НЕ ГОТОВА; покупку не рекомендовать, пока шаги 1–4 не выполнены.**
