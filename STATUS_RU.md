# Vault Exporter — проверяемый статус на 25 октября 2026

## Что действительно работает

- **На телефоне пользователя (подтверждено видеозаписью):** установка и запуск офлайн-демо Android, разрешённая запись экрана, рабочая кнопка диагностики, успешный ответ JNI + официальной TDLib `TDLIB_OFFLINE_PROBE_PASS`.
- **На GitHub Actions:** офлайн-проверки и компиляция кода; ранее собран настоящий arm64 APK с проверенным нативным TDLib. Положительный статус означает только перечисленные тесты, а НЕ проверку реального экспорта.
- **В исходниках:** `getChatHistory` / `downloadFile`, локальное шифрование TVA, шифрованное staging-хранилище, возобновление, проверка целостности, отказ от ложного успеха при неизвестных типах файлов.
- **Новое, ещё не проверенное на телефоне:** кнопка «Создать проверочный архив .tva (офлайн)» создаёт настоящий зашифрованный файл из трёх ВЫМЫШЛЕННЫХ сообщений и одного фиктивного вложения, затем проверяет открытие, структуру и целостность без Telegram. Пароль ТОЛЬКО для вымышленного учебного архива: `Vault-demo-archive-only`.

## Строгая изоляция

- Обычный `debug` APK **не имеет** Android permission `INTERNET` (манифест src/debug), кнопка логина недоступна, исходный аккаунт Telegram не затрагивается.
- Отдельный `sandboxDc` APK (пакет `org.vault.exporter.sandbox.testnet`) **имеет Интернет**, подключается исключительно к `use_test_dc=true`, и не является пригодным к production Telegram.
- Пробная сборка с заведомо недействительными API-ключами используется ТОЛЬКО для проверки компиляции, НЕ для реального экспорта и НЕ для установки пользователем.
- `main` без изменений, вся активная разработка в `work/vault-exporter-replayed-20261024`.
- Нельзя обещать нулевой риск санкций Telegram либо полной защиты от утечек. Тестировать на основном аккаунте запрещено до отдельного одобрения после проверок.

## Что пока НЕ готово

- Реальная авторизация на тестовых дата-центрах **не проводилась**, нет доказательства скачивания даже одного облачного Telegram-чата.
- Нет независимой проверки сети и стороннего аудита безопасности, тестов выгрузки многих гигабайт на настоящем телефоне и фонового сервиса.
- Исходный `.tva` не является форматом HTML/JSON Telegram Desktop, для существующего Reader нужен адаптер.
- Для реального сетевого теста **разработчику** нужны зарегистрированные API ID и API Hash; конечному пользователю не должны требоваться GitHub или API-ключи.
- Сценарий упаковки зависит от короткоживущего артефакта официальной TDLib; необходимо перестроить устойчивый механизм сборки из фиксированного коммита перед выпуском.

## Следующие технические критерии приёмки

1. Сохранить учебный `.tva` на Android, открыть его обратно, проверить шифрование, структуру и повреждения.
2. Проверить `sandboxDc` без ввода реального номера; убедиться, что даже ошибочный режим сборки не направляет запросы в production.
3. На изолированной тестовой учётной записи и разрешённых фиктивных данных выполнить реальную выгрузку и проверить воспроизведение и SHA-256 каждого файла.
4. Исправить ошибки под реальные запросы Telegram, затем тестировать фоновые прерывания/дисковое пространство, аудит трафика, полный security review.
5. Только после пунктов 1–4 решать вопрос об отдельной версии для обычных аккаунтов и интеграции в существующую читалку.

**Не выдавать функциональность фиктивных тестов за проверенную реальную выгрузку.**
