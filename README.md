# Vault Exporter v0.9 — безопасное начало тестирования (исходники, НЕ APK)

## Что изменилось

**По умолчанию приложение собирается ТОЛЬКО для тестовых дата-центров Telegram** (`telegramEnvironment=test`). Эта сборка имеет отдельный Android package ID `org.vault.exporter.sandbox`; тестовая база и сеанс не смешиваются с production.

**Подключение не выполняется автоматически.** При открытии только офлайн-интерфейс: «Посмотреть как работает экспорт» (не обращается к Telegram) и «Подключить тестовый Telegram» (отдельное явное подтверждение). До нажатия соединения через TDLib нет.

Продакшен-сборка намеренно заблокирована по умолчанию. Снять блокировку можно только при явной настройке сборки `telegramEnvironment=production` И `approveProductionBuild=true` после отдельной ревизии и реальных испытаний. Это *технический предохранитель от случайного использования основного аккаунта*, а не гарантия отсутствия риска Telegram.

Ранее написанный экспорт (`getChatHistory` + `downloadFile`, зашифрованное промежуточное хранилище, архив `.tva`) сохранён. **Takeout API пока не интегрирован.** Реальная Android-сборка, совместимость с последней TDLib и авторизация на тестовых серверах пока не проверены.

## Почему это важно

Telegram прямо предупреждает о контроле неофициальных API-клиентов: https://core.telegram.org/api/obtaining_api_id . Даже при строго разрешённом экспорте 0% риска блокировки никто гарантировать не может.

У Telegram предусмотрены изолированные Test DC: https://core.telegram.org/tdlib/docs/classtd_1_1td__api_1_1set_tdlib_parameters.html . Существуют противоречивые сведения об актуальной доступности публичных тестовых номеров `+99966...` (некоторые разработчики сообщают, что они перестали работать), поэтому НЕ предполагаем, что они наверняка доступны, и не предлагаем вводить настоящие секреты в общедоступные тестовые аккаунты.

**Новый порядок тестирования:**
1. Офлайн-демо и статические тесты без аккаунта.
2. Сборка и установка test-DC APK, ревизия зависимостей и разрешений.
3. Авторизация на изолированном тестовом DC только при его доступности, фиктивные сообщения/файлы.
4. Контроль сетевых запросов и локального кэша, рестарт/ошибки, независимая проверка APK.
5. ТОЛЬКО после этого — отдельное решение о production; тестировать на основном аккаунте без принятия риска не нужно.

**Дополнительные риски:** неизвестная полнота Telegram Cloud-истории, временные нешифрованные копии TDLib, закрытое хранилище устройства и наличие потенциальных багов. Независимого аудита нет. Приложение не должно называться полностью безопасным на этом этапе.

## Как проверить локально

`python3 scripts/security_gate.py` — статический стоп-кран, не аудит.

`javac ...` и четыре JVM-теста доступны из предыдущей версии.

**Готового APK в комплекте нет:** для компиляции необходимы Android SDK, NDK и подлинная TDLib `libtdjson.so`; сценарий CI лежит в `.github/workflows/build-debug-apk.yml`.

## CI без аккаунта и секретов

`.github/workflows/offline-security-tests.yml` запускает только локальные тесты архивирования и политики доступа при push/PR. **Telegram API ID/Hash и любые чаты не требуются.** Эта проверка должна пройти первой; сам APK появится только после сборки native TDLib и Android CI.
